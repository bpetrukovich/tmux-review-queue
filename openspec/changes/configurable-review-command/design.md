# Design

## Context

Команда ревью зашита в `domain/workspaces.py:26`; спецификация фиксирует `nvim +'DiffviewOpen <base>..<ref>'`, в workdir при этом лежит незакоммиченный эксперимент с `CodeDiff`. Домен обязан оставаться чистым (AGENTS.md: без subprocess/fs/env). Соседний `multi-sessionizer` уже задаёт целевой паттерн: `infrastructure/config_loader.py` (томllib, env-переопределение пути), `app/configuration.py` (DTO + `ConfigError`/`ConfigNotFoundError`), `infrastructure/messages.py` (`CONFIG_EXAMPLE`-скелет). Python >=3.12 — `tomllib` в stdlib, новых зависимостей нет. Мотивация — proposal.md «Why», контракты — delta-спеки.

## Goals / Non-Goals

**Goals:**
- Обязательный TOML-конфиг по конвенциям msz; шаблон `[review].command`; плейсхолдеры только `{base}`/`{ref}`; строгая валидация; скелет при отсутствии файла.
- Валидация и подстановка — чистые функции в домене, полностью покрытые юнит-тестами.

**Non-Goals:**
- Никаких дополнительных плейсхолдеров (`{repo}`, `{path}`, `{id}`) — остальное приходит только из task-JSON.
- Никаких правок `multi-sessionizer`, его конфига или стора.
- Никакого встроенного дефолта команды — конфиг обязателен, «no built-in defaults» как в msz.

## Decisions

1. **Путь и env зеркалят msz**: `~/.config/tmux-review-queue/config.toml`, переопределение через `TMUX_REVIEW_QUEUE_CONFIG`. Одна конвенция на оба инструмента, привычный путь для пользователя. Альтернатива «флаг `--config PATH`» отклонена — env покрывает тот же случай без нового CLI-аргумента.
2. **Ключ — секция `[review].command`**, а не плоский `review_command`: секция оставляет место будущим ключам (например `window_name`) и группирует связанное. Плоский вариант отклонён.
3. **Конфиг обязателен**: нет файла → скелет в stderr + exit 1, ничего не регистрируем. Это сознательный BREAKING (решение пользователя, msz-философия). Альтернатива «опциональный конфиг со встроенным дефолтом» отклонена.
4. **Подстановка — однопроходный `re.sub(r"\{base\}|\{ref\}", repl, template)`** с lookup-функцией по словарю, а не `str.format` и не цепочка `.replace`: (a) пользовательский шаблон может содержать литеральные `{}`/`{...}`-секвенции, которые `.format` сломает или заставит экранировать; (b) однопроходность исключает двойную подстановку, если значение одного плейсхолдера содержит строку другого.
5. **Валидация — чистая функция в новом `domain/review_command.py`**: `re.findall(r"\{([^{}]+)\}", template)` → требуем ровно `{base}` и `{ref}`, каждый незнакомый `{...}` — ошибка. Возвращает `list[str]` проблем, как `parse_task`. Пустые `{}` не матчатся — остаются как есть.
6. **Поток**: `main`/`_add_dispatch` загружает конфиг до `add_flow`; ошибки конфига → exit 1 (как у msz «configuration problem»), `--help` работает без конфига. `FlowDeps` получает `config: ReviewConfig`; `add_flow` → `group_yaml(task, command)` → `workspace_yaml(repo, task, command)`. Тесты по-прежнему инжектят `FlowDeps` напрямую и конфиг не читают.
7. **Скелет — в `infrastructure/messages.py`** (`CONFIG_EXAMPLE`), как в msz; пример команды — каноническая `nvim +'DiffviewOpen {base}..{ref}'` (значение скелета можно переопределить в проде, это только подсказка).

## Risks / Trade-offs

- [BREAKING: существующий пользовательский флоу требует новый файл] → скелет в stderr + секция в README с примером.
- [Сырая подстановка base/ref в shell-строку tmuxp] → риск инъекции существовал и до конфига (base/ref валидируются лишь как непустые строки); конфиг доверенный, task — локальный (AI-отчёт). `shlex.quote` неприменим — сломает шаблон вида `nvim +'CodeDiff {base} {ref}'`, где кавычки принадлежат шаблону. Ограничиваемся документированием.
- [Незакоммиченная правка `CodeDiff` в workdir] → имплементация идёт от HEAD на отдельной ветке; локальная правка на main устаревает, команда переезжает в конфиг.
- [Скелет показывает не ту команду, что использует пользователь] → чисто косметика: конфиг обязателен, скелет — подсказка, пользователь пишет свою команду.
