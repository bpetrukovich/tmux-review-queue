# Proposal

## Why

Когда ИИ-агент завершает параллельную работу в нескольких ветках, разработчику нужно быстро ревьюить диффы по всем затронутым репозиториям. Сейчас для этого приходится вручную открывать каждый репо и поднимать diff-сессию. Нужна лёгкая надстройка над multi-sessionizer, которая превращает отчёт агента (задача + список репо/веток) в готовые к ревью tmux-сессии одним действием.

## What Changes

- Новый CLI `tmux-review-queue`:
  - `add <file|stdin>` — принимает JSON-описание задачи от ИИ (`id`, `description`, `repos[]` с `name`, `path`, `ref`, `base`), валидирует его и регистрирует задачу в multi-sessionizer как **named group** внешних записей (external entries) через `multi-sessionizer external add`.
  - Без аргументов — ничего не делает (нет fzf в этом туле).
- Каждая задача превращается в одну msz-группу; имя группы — `task_id·slug(description)` (кириллица сохраняется, slug чистит только пробелы/спецсимволы и обрезает длину). Имена tmux-сессий по репо — `task_id·repo_name·slug(description)`, чтобы описание было видно и в списке сессий.
- `ref` и `base` принимают любую git-ссылку (ветка, тег, хэш коммита, `HEAD`); существование ссылок не проверяем — диапазон разрешает Diffview в момент выбора.
- Члены группы — по одному inline tmuxp-воркспейсу на репо: одно окно `diff`, команда `nvim +'DiffviewOpen <base>..<ref>'`, без переключения веток (`start_directory` = путь репо, репо уже стоит на ревью-ветке).
- Интерактивный выбор (fzf) целиком остаётся ответственностью multi-sessionizer: зарегистрированная группа появляется в его пикере как `[group] <name>`, выбор провижинит tmux-сессии.
- Жизненный цикл в MVP — только `add` (регистрация) + выбор в msz. Статусы/удаление/собственная очередь задач не входят в MVP: **хранилище msz external store и есть очередь** (наивная альтернатива с собственным `tasks.json` отклонена — см. design.md). При дубликате (имя группы уже существует) — ошибка с понятным для ИИ хинтом «измени `id`/`description`, чтобы имя группы стало другим, и повтори», exit 1.
- Ничего в multi-sessionizer не меняется: он используется как чёрный ящик по CLI.
- Новый opencode-скилл «как ИИ регистрирует задачи ревью» (payload, правила нейминга, семантика `ref`/`base`, поведение при дубле) живёт в `.opencode/skills/` репо + инструкция по установке в README.

## Capabilities

### New Capabilities

- `review-queue`: принятие payload задачи ревью от ИИ, валидация и регистрация её как группы review-воркспейсов в multi-sessionizer (генерация tmuxp-схем и делегирование пикера наружу).

### Modified Capabilities

- Нет.

## Impact

- Новый Python-проект `tmux-review-queue` в этом репо: Python 3.12 / uv / PyYAML, слоистая структура как в multi-sessionizer (чистый `domain`, `infrastructure` для subprocess).
- Зависимости на рантайме: установленный CLI `multi-sessionizer`, `tmux`, `tmuxp`, `nvim` c плагином Diffview.
- Новый opencode-скилл для ИИ в `.opencode/skills/` с инструкцией установки в README.
- Не изменяет код, конфиг или API multi-sessionizer.
